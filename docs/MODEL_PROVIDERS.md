# 模型服务与协议设置

> 本文说明当前源码中的模型设置与 Anthropic Messages 接入，不表示这些变更已经发布。

在“小镇设置 → 连接模型 API”中选择服务协议，填写服务地址、模型名称和密钥，再点击“保存连接设置”。保存只更新本机配置，不会自动发送测试消息；你可以随后主动向伙伴发一条消息检查连接。

切换协议不会替换已经填写的服务地址或模型名称。请根据服务商说明核对这两项，尤其是在不同服务之间切换时。

## 选择协议与鉴权方式

| 服务协议 | 适用接口 | 鉴权方式 |
| --- | --- | --- |
| OpenAI 兼容 | Chat Completions 文本对话接口 | 固定使用 `Authorization: Bearer …`。 |
| Anthropic Messages | Anthropic 官方 Messages 接口，或兼容该协议的网关 | 默认使用标准 `x-api-key`；网关要求时可显式选择 Bearer Token。 |

“Anthropic Messages”下的鉴权选项只决定密钥发送在哪个请求头中。两种方式不会同时发送，也不会根据请求失败自动换一种鉴权重试。小镇会附带 `anthropic-version: 2023-06-01`。

模型名称应填写当前账户或网关实际提供的模型 ID。显示名称相似，不代表接口协议或模型名称相同。

没有新增协议字段的旧配置继续按 OpenAI 兼容协议和 Bearer 鉴权读取。保存后的协议和鉴权方式会在重新打开设置时恢复。

## 官方服务示例

以下仅为公开服务地址，不包含密钥。模型名称请使用账户当前可用的准确 ID。

| 设置 | OpenAI 官方服务 | Anthropic 官方服务 |
| --- | --- | --- |
| 服务协议 | OpenAI 兼容 | Anthropic Messages |
| 服务地址 | `https://api.openai.com/v1` | `https://api.anthropic.com` |
| 鉴权方式 | Bearer，固定 | API 密钥，标准 `x-api-key` |
| 密钥 | 自己的 OpenAI API 密钥 | 自己的 Anthropic API 密钥 |

远程服务地址必须使用 HTTPS。HTTP 只允许 `localhost` 或 `127.0.0.1` 的本机服务，例如 OpenAI 兼容本机模型地址 `http://127.0.0.1:11434/v1`。本机服务是否需要密钥，取决于服务本身。

## Anthropic 地址如何填写

小镇会保留网关自定义路径前缀，再按 Messages 协议生成请求地址。可以填写根地址、以 `/v1` 结尾的地址，或完整的 `/v1/messages` 地址。

| 填写的服务地址 | 实际 Messages 请求地址 |
| --- | --- |
| `https://api.anthropic.com` | `https://api.anthropic.com/v1/messages` |
| `https://api.anthropic.com/v1` | `https://api.anthropic.com/v1/messages` |
| `https://api.anthropic.com/v1/messages` | `https://api.anthropic.com/v1/messages` |
| `https://gateway.example.com/team/anthropic` | `https://gateway.example.com/team/anthropic/v1/messages` |
| `https://gateway.example.com/team/anthropic/v1/messages` | `https://gateway.example.com/team/anthropic/v1/messages` |

`gateway.example.com` 是文档示例域名，不是可用服务。网关必须提供对应路径和 Messages 响应格式；仅填写网关首页不能保证兼容。

地址不能包含用户名、密码、查询参数或片段。密钥放在密钥输入框中，不放进 URL。小镇不跟随服务返回的重定向；服务迁移后需要填写正确的最终地址。

OpenAI 兼容协议沿用原有规则：在填写的 API 前缀后使用 `/chat/completions`，不会自动补上 `/v1`。官方 OpenAI 示例因此保留 `/v1`；如填写完整 `/chat/completions` 地址，小镇会先去掉该接口后缀。

## 密钥保存与切换

macOS 使用系统钥匙串，Windows 使用凭据管理器。页面只显示是否已经设置，不会回填已保存密钥。没有系统密钥存储能力的平台可按页面说明使用 `STARHAVEN_API_KEY` 环境变量。

留空表示不提交新的密钥，继续沿用该服务可取得的已有凭据。切换到其他服务后，需要确认对应服务已经配置有效凭据。保存完成或失败后，刚填写的密钥都会从输入框清空；失败时连接选项保留，若需要重新提交密钥，应再次输入。

## 当前 Messages 支持范围

普通聊天保留完整文字响应；分步工作在当前连接通过功能验证后使用流式响应及图片内容块。发送顶层 `system`、用户消息和输出上限，接收并合并最终文字。思考内容和工具调用块不会作为普通文字展示，也不会触发工具执行。

如果回复因输出或上下文上限而截断，或模型要求调用工具才能继续，小镇会提示未完成，不会将部分内容当作完整成果。文档在本机提取，流式和看图分别验证；见[分步工作与功能验证](RESIDENT_INTERACTIONS.md)。

## 聊天兼容与研发、训练权限

**协议兼容可用于聊天；受控研发、训练仍需用量适配与授权。** Messages 能返回文字或用量字段，并不证明任意服务已经具备小镇所要求的预算约束。

受控预算保留已适配官方模型的静态档案，也支持通过显式本机用量验证的 Messages 文本连接。本机档案只匹配保存后的服务地址、协议、鉴权方式和模型这四项，不会让其他网关或模型继承验证结果。模型设置会显示已保存连接的适配状态；验证有效也仍需完成培养网络授权，发送源码还需项目授权。

保存协议设置不会启用自动训练、扩大居民权限、允许新的模型端点或授权发送项目源码。切换协议、鉴权、模型或服务后，关联授权需要按实际入口重新核对；不能把旧服务的授权直接视为新服务已获准。

## 本机用量验证（维护者）

先在小镇设置中保存目标 Messages 连接，再从源码目录运行维护命令。`--data-dir` 应指向这台电脑实际使用的小镇存档目录：

```sh
python3 scripts/verify_model_budget.py --data-dir "<本机存档>" --verify
```

显式传入 `--verify` 才会向已配置的模型服务发送合成文本请求并产生模型用量；省略它只查看现有验证状态。验证不读取项目源码，也不会自动创建或启动研发、训练任务。

验证后，在设置中再次保存当前连接，或重新启动小镇，即可读取最新适配状态。

通过后，验证档案及用量证据保存在该私有数据目录的 `model-budget-verifications.json`，有效期为 **30 天**，适用范围仅为非流式 Messages 文本。默认验证保持原有的 **4096 Token** 输出和 **65536 字节**完整请求上限；需要更大研发输出时，显式执行扩展验证：

```sh
python3 scripts/verify_model_budget.py --data-dir "<本机存档>" --verify --output-limit 32768 --input-limit 262144
```

| 本机验证范围 | 单次最大输出 | 完整序列化请求上限 |
| --- | --- | --- |
| 默认验证 | 4096 Token | 65536 字节 |
| 扩展验证 | 32768 Token | 262144 字节 |

两个上限按表中组合验证，旧档案不会自动升级。扩展验证后仅受控研发请求可使用最多 600 秒的等待上限，聊天与训练仍最多 120 秒。维护验证会产生模型用量；通过验证也不保证每次回复都能在上限内完整生成。

研发台的“研发额度”支持常规与放宽模式。常规模式使用培养设置的次数与 Token 上限；放宽模式仅免除研发的每日调用次数、每日 Token、累计 Token 和单次总额上限，输出额度可选 4096、8192、16384、32768 Token，默认 32768。研发单独记账，不占用聊天与训练额度；两种模式都继续核验用量，实际请求仍须满足当前模型适配档案的上限及原生授权。详见[研发额度与用量](DEV_WORKBENCH.md#研发额度与用量)。

验证记录的是合成样本表现，不是供应商计费保证。每次受控回复仍会核对用量；发现缺失、格式异常或超限会拒绝成果、撤销本机档案并暂停受控调用。网络中断或 HTTP 错误按未知用量保留预留额度，不据此认定服务违反用量约定。

验证失败或过期时，受控调用不会借用旧结论继续执行。更换服务地址、协议、鉴权方式或模型后，需要为新的连接重新验证。该档案不随小镇状态包迁移；换电脑或数据目录后，应在目标环境重新验证。它不包含密钥，也不替代居民、端点、模型及源码的原生授权。

## 常见情况

| 情况 | 检查方向 |
| --- | --- |
| 保存成功但还没收到模型回复 | 保存不会测试服务；主动发送一条消息后再查看结果。 |
| 提示鉴权失败 | 核对密钥属于当前服务，以及网关要求 `x-api-key` 还是 Bearer。 |
| 地址不存在或返回非对话内容 | 核对协议、服务前缀和最终接口路径；不要把控制台网页地址填成 API 地址。 |
| 模型不存在 | 使用服务端实际提供的模型 ID，而非产品展示名称。 |
| 回复达到上限或要求工具 | 缩小问题、调整获准的输出上限，或要求模型直接输出文字；当前不会替模型执行工具。 |
| 普通聊天可用，研发或训练受阻 | 查看受控预算适配、居民权限、允许的端点及剩余额度；协议兼容本身不会解除这些限制。 |
| Messages 本机验证失效或更换电脑 | 在当前环境核对已保存连接，重新运行维护验证；成功后再核对培养网络及源码授权。 |
