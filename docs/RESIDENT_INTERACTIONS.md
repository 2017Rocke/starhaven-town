# 居民分步工作与本机技能

适用于 2.3.0。短问题继续使用普通聊天；长文档、需求和需要核对资料的任务使用聊天旁的 **分步工作**。入口对全部居民开放，实际模型调用仍遵守居民、服务和预算授权，不因打开工作区自动授予权限。

## 从资料到可核对的结论

1. 输入这次目标，上传 TXT、Markdown、DOCX、PDF、PNG/JPEG/WebP，或者粘贴截图。每份文件最多 20 MiB，每个任务最多 16 份。
2. 上传仅将资料保存在本机，可先预览文字、图片和原件。Word 保留段落、表格及嵌入图，PDF 保留文字和页面渲染图；超出提取范围会提示拆分，不会标为完整读取。
3. 点击开始才会调用已配置的模型。长资料按片段处理，再合并、去重和核对冲突；每步保存结果与来源，页面展示已完成步骤和当前接收状态。
4. 结论区区分事实、推断与待澄清问题。引用可回到原文片段。回答问题后，相关步骤会重新分析，旧分析不能用于确认新答案。
5. 可以暂停、继续或修订目标。连接中断、504 或输出未完成时保留已完成步骤，显式继续后才重试当前部分；连续失败达到本片段尝试边界时，应缩小材料或修订任务。

“接收到文字”只是进度，完整响应、用量和来源检查通过才算完成。界面不显示或保存模型隐藏推理。每个居民保留自己的岗位信息，复杂工作能力相同不代表拥有相同源码、网络或部署权限。

## 图片与流式能力

图片会在本机净化和缩放，去掉原始元数据。发送模型只在任务实际执行时发生。当前配置的模型必须经过合成图像验证，才能接收这些图片；验证未通过时，图片步骤会暂停并明确显示“尚未读取”，不会把文字提取成功误报为理解截图。

流式适配支持 OpenAI Chat Completions 和 Anthropic Messages。没有验证流式时，文字仍可使用原有完整响应方式。流式不能保证消除所有上游 504：网关仍可能设置固定时限。步骤拆分和进度保存用于减少失败后的重复工作。

维护者先安装源码依赖并核对文字预算适配，然后执行：

```sh
python3 -m pip install -r requirements-runtime.txt
python3 scripts/verify_model_features.py --data-dir "<本机存档>" --verify
```

每种功能发送两次合成请求并产生模型用量，不发送用户文档。可用 `--feature streaming` 或 `--feature vision` 单独核对；省略 `--verify` 只读状态。功能验证按地址、协议、鉴权和模型绑定 30 天；不授予网络、居民或源码权限，不随状态包迁移。视觉请求每步最多 4 幅清洗图片，并以固定的每图用量预留和响应核验控制预算。

## 杨辉的需求分析

研发台创建或修订需求时可以附上业务文档和原型截图。需明确确认它们可分享给本项目产品、开发和测试角色；源码截图属于私有开发材料，不应上传成共享需求。

杨辉的分析复用分步引擎；暂停、继续、答疑及确认仍通过研发任务入口操作，不能在普通居民工作区绕过需求版本规则。答复后需要重新分析当前需求，确认后才能进入开发。吉吉生成和应用本地候选修改仍使用原有源码授权与原生确认，提交由用户完成。真实部署和测试执行器尚未接入。

## 吉吉的技能工作区

开发岗位或被项目绑定为开发角色的居民可打开聊天旁的 **技能工作区**。系统发现本机 `~/.codex/skills` 中支持的研发指南：Java 编码、金额逻辑审计、交付文档、Fortress 自测、测试排障、生产排障及小镇发布。列表不会自动导入或启用所有技能。

选择导入后，资源以不可变版本保存在该居民的私有工作区，记录来源及文件指纹。更新源文件后重新导入会生成新版本，旧聊天仍指向原先版本。环境文件、密钥及其他私密依赖不复制；依赖不完整时显示说明，不能当作完整运行环境。

每次聊天最多选择 3 个技能，并可选所需 Markdown 参考资料；总文字不超过 48 KiB。发送成功后清空本次选择，重试同一次请求仍使用原选择。导入不等于启用，启用只把选定指南作为本次模型参考，**不会执行技能脚本、直接运行命令、自动提交代码或扩大权限**。模型不能声称已经执行指南中描述但没有执行器的操作。

文档、会话、导入技能和个人模型记录保存在应用数据目录。桌面升级保留这些内容；公开源码、安装包及通用小镇状态包不包含这些私有材料。完整备份请先退出应用再复制整个数据目录。
