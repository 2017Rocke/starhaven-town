# 警察署与稽查署

两位警官分别拥有房屋、工作区、检查任务和档案视图。警察署检查受管理文件中的执行、权限和指令诱导线索；稽查署检查同一范围文件中的疑似密钥与外发线索，并记录小镇实际发出的 GitHub 采集与模型 API 请求核查。两位警官的聊天回复不构成有效检查结论。

## 使用方法

升级后，巡检警官与网安稽查官会入住可用地块，原居民位置和资料保留。地块不足时会显示待入住提示，不移动原居民。点击两署建筑或治安入口，分别查看档案、启动巡检或设置每日时间。

每日文件巡检默认开启，北京时间警察署 09:30、稽查署 10:00，可在各署独立关闭或改时。小镇关闭后暂停；重新打开后，达到当天设定时间且当天尚未启动过检查的署会执行一次，不补往日任务。手动启动也计入当天安排；当天失败或中断的检查需要手动重试，不会自动重复启动。关闭每日安排只影响定时文件巡检，已接入的网络请求仍会在发送前核查。

巡逻动画表达实际文件巡检阶段，检查结束后显示返署；动画位置不决定检查是否通过。重启后，未结束的检查会记录为中断，画面按保存的任务状态恢复，不会自动续扫。减少动态效果的系统偏好会被尊重。

## 文件检查范围

扫描范围由程序限定，涵盖数据目录内的 `scout-workshop/materials/`、居民工作区的指定子目录，以及已配置的研究报告目录。不会递归扫描整台电脑，也不会执行下载的源码、安装依赖或照做文档中的指令。

居民工作区位于数据目录的 `workspaces/<居民编号>/`。程序会创建并检查其中的 `skills/`（技能）、`books/`（书本）、`materials/`（材料）和 `results/`（结果）四类子目录；直接放在居民工作区根目录或其他位置的文件不在覆盖范围内。检查结果列出实际检查量、跳过原因与限制。没有可扫描文件时不出具通过结论；超出上限、二进制、符号链接、敏感路径或读取失败的内容会标明未覆盖。

静态规则寻找疑似密钥、危险下载执行、敏感信息外传以及文档诱导等线索。命中需要复核，未发现线索不代表没有漏洞。当前版本不提供完整恶意软件识别、依赖漏洞数据库扫描或运行时行为沙箱。

## 独立档案与内容变化

原木、工具和书本不会保存可由居民改写的“检查通过”字段。检查程序在独立的 `security-office/` 中追加记录，按两署区分归属；公开接口只允许查看档案、发起检查和修改巡检时间，不能上传结论、覆盖记录或删除历史。

文件记录绑定相对位置、内容 SHA-256、规则版本、检查时间和范围。当前规则版本为 `1.11.0-r1`。文件改变或消失后，查询显示过期或缺失；规则更新后，即使内容未变，旧文件记录也会提示需要重新检查。历史记录仍保留，重新检查会生成新的记录。扫描过程中发生修改或无法完整读取时应视为覆盖不完整。

记录使用追加写入约束和前后关联摘要检测损坏。检测到完整性异常时停止出具新的有效检查结果，并暂停受监测的网络发送。此机制用于防止应用内擅改以及检测普通磁盘损坏，不是抵御拥有本机管理员权限的人重写程序和整个数据库的可信硬件证明。

## 网络核查范围

- GitHub 采集仅访问既有官方公开 API 与源码下载域名，不携带 GitHub 密钥，继续禁止重定向。
- 模型 API 仅发送到镇长配置的服务地址；认证头不写入档案。请求正文出现明显密钥或包含当前认证密钥时会暂停发送。用户配置的本机模型仍可使用本地 HTTP。
- 审计记录不保存请求正文、认证头、URL 查询参数或远端错误正文；可查看居民、目的地主机、用途、方法、规则决定和请求结果。
- 本机 Codex 对话属于外部程序调用，小镇仅记录“外部调用、实际网络未覆盖”；不会把外部程序的请求冒充为已检查。
- 发送前检查或落档失败时不发送；发送后的结果落档失败时提示错误，不返回本次结果，也不绕过检查重试。

现有居民没有通用脚本执行器或任意网络工具。未来增加工具执行、第三方插件或新请求入口时，必须在发送前接入同一检查服务，并补充阻断、取消、重定向和脱敏测试。独立运行的其他程序与系统流量不受本功能监控。

## 发现问题后

文件发现仅生成待复核记录，不自动删除、移动或隔离文件。已阻断的网络请求可在稽查署查看原因；修正材料或连接配置后再重试。当前版本不提供居民可自行点击的“忽略规则并通过”按钮。

两署使用各自档案和日报交接。文件静态检查与网络请求核查是两种不同结论，不能相互替代。
