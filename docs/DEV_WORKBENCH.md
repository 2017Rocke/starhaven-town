# 研发台使用说明

> 适用范围：当前源码中的研发台实现，更新于 2026-11-16。功能范围随 2.3.0 发布。

研发台把一条需求的原文、版本、疑问、测试计划、候选代码修改和讨论记录放在同一本工作簿里。入口是左侧导航的 **研发台**。

目前可以完成 **需求整理、答疑、确认、测试方案、获准源码编辑、检查候选差异及确认应用本地修改**。代码提交与推送由你自行完成。**真实功能自测执行器、提交验证、部署连接器和独立验收连接器尚未接入**，因此当前实现不能称为自动研发全闭环。

## 开始前

1. 使用小镇桌面窗口。需求资料可以在页面中查看；连接源码、应用本地修改必须在桌面原生确认窗口完成。
2. 在“小镇设置”中配置 API 服务地址、模型和必要凭据。研发调用要求可核验用量的受控 API 模型；仅普通聊天可用，并不表示该模型已满足研发调用要求。本机 Codex 外部进程模式不能用于这些受控调用。
3. 在“成长册 → 培养与网络设置”中确认参与居民、允许的模型服务与模型名称，以及预算。杨辉、吉吉和李力必须位于允许范围内，调用权限不能处于暂停状态。研发台复用这份调用权限；常规模式采用这里的额度上限，但研发与聊天、训练分开记账。不要求开启成长署的自动训练。
4. 准备一个范围清楚的本地项目。建档和整理需求不需要源码授权；开始开发前再连接指定目录。

如果模型服务不支持受控预算、居民尚未获准、额度不足或连接失败，执行记录会显示失败或受阻。不会退回到不受控的终端调用。

模型设置可选择 Anthropic Messages 协议及对应鉴权。指定连接通过本机用量验证、且验证仍在 30 天有效期内时，可用于受控研发；居民、端点、模型和源码的原生授权仍须有效。本机验证只覆盖 Messages 文本。原有档案覆盖最多 4096 Token 输出、65536 字节完整请求；需要更大输出时，须另行通过 32768 Token 输出、262144 字节请求的扩展验证。旧档案不会自动升级，较大的需求与修改仍应按范围拆分处理。验证方法与连接说明见[模型协议说明](MODEL_PROVIDERS.md)。切换服务、协议、鉴权或模型后需要重新验证对应连接并核对源码授权；验证档案不随状态包迁移。

### 研发额度与用量

点击研发台顶部的 **“研发额度”**，选择模式与放宽模式的单次最大输出，再点击 **“核对并保存研发额度”**。在桌面原生窗口确认后，页面刷新并显示实际生效的模式与单次输出额度。仅提交确认请求不会提前应用新设置。

| 模式 | 次数与 Token 额度 | 单次输出 |
| --- | --- | --- |
| 常规 | 按培养设置中的每日调用次数、每日 Token、累计 Token 和单次总额上限执行；研发单独记账。 | 沿用培养设置的输出上限。 |
| 放宽 | 研发不受上述四项上限限制，继续记录调用与用量；聊天与训练继续使用原额度。 | 默认 32768 Token，可选 4096、8192、16384、32768。 |

研发用量不会占用聊天与训练的额度。切回常规模式不会清空已有研发用量记录。放宽模式仍受模型适配档案的输出与请求大小上限约束，选择较大额度不代表模型已经支持；旧 4096 Token 验证档案不能直接支持更大输出。

暂停控制、居民与模型服务授权、源码权限以及每次调用的用量核验继续生效。文件数量、可读取内容、执行轮数和候选修改等边界也继续保留。这项设置只放宽研发的次数与 Token 额度，不会自动开始任务，也不会授权新的源码或模型服务。

## 1. 建立项目并选择小队

点击 **“＋ 为项目建档”**，输入项目名称，再逐一选择产品、开发、测试和总览居民。通常分别对应杨辉、吉吉、李力和领航。

下拉列表同时显示居民名称和固定标识。请选择存档中已有的正确居民；四个选择不会按姓名自动填写，也不会新建居民。李力与其他居民是不同记录，同名或近似名称不代表同一个成员。旧存档中的居民可以保留原标识、外观和聊天记录。

项目建立后，左侧显示已绑定的成员与需求列表。普通聊天仍是聊天；需要执行研发动作时，请使用研发台中的对应按钮。

## 2. 保存需求、分析与答疑

点击 **“＋ 添加需求”**，填写需求名称，将业务背景、期望行为和完成标准粘贴到“原始需求”中，点击 **“保存需求”**。

点击 **“分析需求”** 后，杨辉按资料片段生成需求摘要、范围、验收标准和需要你决定的问题，再归并复核。长需求涉及多次实际模型调用，步骤结果保存到当前需求版本，支持暂停和继续；问题不足时可以没有疑问，分析完成不等于需求已经生效。创建和修订可导入业务文档或图片，上传成功与模型理解完成分开显示，详见[分步工作](RESIDENT_INTERACTIONS.md)。

在“待答疑问”中填写并 **“保存回答”**。标记为“确认前需回答”的问题必须答完。答复使相关旧分析失效，需重新分析核对后才能确认；已有答复进入记录，业务规则需要改变时应提出新需求版本。

分析完成且必答问题已解决后，点击 **“确认需求”**。页面会分别显示：

- **当前草稿**：最近保存的需求版本。
- **生效需求**：你已确认、用于开发和测试计划的版本。
- **当前责任人**：目前等待哪位成员或你本人处理。

已完成分析的同一版本不能反复点击分析。可以回答剩余问题，或创建新的需求草稿。

## 3. 生成测试方案

确认需求后，点击 **“生成测试计划”**。李力根据生效需求、已回答的业务问题和获准共享资料，整理测试范围与用例，包括操作步骤、预期结果和优先级。

计划保存在“需求分析与测试计划”中，并标明对应需求版本。**生成测试计划只是保存用例，没有访问测试环境，也没有执行这些用例。** 旧版本计划仍可查看，但不能证明新版本已通过验收。

## 4. 连接源码仓库

点击项目左侧的 **“连接代码仓库”**：

1. 填写仓库短名和本机目录。短名使用英文、数字、下划线或短横线，例如 `app`；一个项目可连接 1 至 6 个不同目录，目录不能重复或相互包含。
2. 核对页面显示的当前 API 模型。勾选允许这些仓库的源码发送给该模型，用于当前项目研发。
3. 点击 **“核对并连接仓库”**，在桌面原生窗口核对仓库、项目成员和模型范围，再决定是否确认。

浏览器中的按钮只提出确认请求，不会直接授予源码权限。若确认期间仓库或模型等关联状态发生变化，需要重新核对。模型服务、模型名称或开发成员改变后，原授权不能直接用于新的开发范围。

只有绑定的开发角色通过受控执行器读取源码。产品与测试角色获得需求、问题答复和共享文稿；领航获得进度摘要。开发候选差异与私有开发疑问不会作为共享资料自动发送给其他居民。请将源码留在获准目录中；原始需求和产品问题属于共享业务资料。

### 断开源码授权

已连接的项目显示 **“断开源码授权”**。点击后停止该项目后续源码访问，阻断待执行或进行中的开发，并使旧候选修改不能继续应用。再次开发需要重新连接并完成原生授权。

断开不会删除用户仓库或既有工作记录，也不会撤销已经写入的本地修改。**此前已经发送给模型的请求或内容无法收回。** 取消一条需求与断开整个项目的源码授权是两个不同动作。

## 5. 生成并检查吉吉的候选修改

生效需求必须与最新草稿一致，所有必答问题必须解决，源码授权也必须有效。满足这些条件后，点击 **“生成本地修改”**。

吉吉可以在受控范围内查找和读取文本源码，提出已有片段的替换或新文件内容。修改先保存为私有候选内容，**此时尚未写入你的项目文件**。当前执行器没有任意终端、Git 写工具、依赖安装、构建、测试命令或部署工具，也不支持任意文件类型与删除、移动文件。

如遇需要你决定的业务问题，吉吉可以暂停并留下开发疑问。回答后再次点击“生成本地修改”，系统会在适用的需求版本、授权和本地基线下继续处理候选内容。

在“执行记录”中点击 **“检查本地修改”**，查看摘要、差异和检查情况。候选成果保存完成只说明这次编辑结果已记录。当前功能自测应显示 **“未执行”**；模型描述“完成”不能替代运行证据。

每批开发有轮数和修改范围限制。达到上限、文件过大、路径不在允许范围、遇到链接或读取失败时，执行会停止并记录原因。必要时拆分需求，不会自动扩展到整个电脑或运行任意命令。

## 6. 确认应用，然后自行检查提交

确认候选差异符合预期后，点击 **“核对并应用本地修改”**，在桌面原生窗口确认这一次具体修改。

应用前会重新核对需求版本、开发批次、源码授权与目标文件的原始内容。出现新的需求、返工反馈、更新的开发批次或本地编辑时，旧候选可能失效，不能直接覆盖当前内容。

应用成功后，状态变为 **“等待你检查提交”**。你需要在自己的开发工具中检查文件、运行项目所需的验证，并自行提交、按需要推送代码。研发台不会执行 commit、push、merge 或 tag；目前也不会核验你已经提交的版本。

如果应用中断，详情会显示“已记录写入的文件”和可能保留的恢复文件路径。请先检查本地差异与恢复文件。一次多文件应用可能已写入部分内容，系统不会把中断视为全部回滚，也不会自动重放这一批修改。不要将“没有记录完成写入”理解为本地一定没有变化。

## 7. 提需求变更或要求返工

业务范围变化时，展开“需求版本 → 提出需求变更”，填写 **完整的新需求**，点击 **“提交变更”**。这会生成新草稿；在你重新分析、回答问题并确认前，原生效需求仍然保留。新的开发必须先确认最新草稿。

只是要求修正实现时，在“讨论记录”中填写“给吉吉的修改意见”，点击 **“请求吉吉修改”**。反馈会记录为返工要求，使旧开发候选失效。此按钮不会直接启动下一轮源码编辑；确认条件满足后，再点击 **“生成本地修改”**。

不要直接应用有未解决开发疑问的候选内容。每次新的本地应用仍要经过当前批次的原生确认。

## 8. 状态、重试和关闭小镇

| 页面显示 | 含义与处理 |
| --- | --- |
| 排队中 / 执行中 | 后台有真实作业；切换页面不会把作业标为完成。 |
| 等待确认需求 | 当前分析已保存，需要答疑或确认版本。 |
| 开发阶段 / 当前阻塞 | 表示工作所在阶段；结合阻塞说明判断是否已有实际开发，不能只看阶段名。 |
| 候选修改已完成 | 候选内容已保存，仍需检查和确认应用；不代表自测或验收通过。 |
| 等待你检查提交 | 本地应用已记录，下一步由你检查、验证和提交。 |
| 受阻 / 未完成 / 执行中断 | 查看原因，处理权限、预算、文件或连接问题后，可重试仍适用于当前版本的工作。 |
| 记录已更新 | 本次操作未覆盖新版本。输入已保留，核对最新内容后再继续。 |

保存期间继续输入的内容会保留。网络结果不明时，相同操作的重试沿用原请求标识；版本冲突不会自动用旧草稿覆盖新内容。

有进行中作业时，“取消这条需求”取消的是整条需求，不是暂停单次调用。已取消需求不会通过重试继续执行，历史记录仍保留。关闭小镇会停止当前进程中的工作；重启后，原执行中工作标为中断，已持久化的排队工作仍可能被调度。后台不是关闭应用后持续运行的服务。

页面只在研发台可见时刷新记录；后台作业由小镇服务执行，不依赖页面轮询或人物动画。

## 当前交付边界

| 能力 | 当前实现 |
| --- | --- |
| 项目、小队、需求版本、答疑、确认、讨论 | 已接入持久化工作记录。 |
| 产品分析与测试计划 | 真实受控模型调用，结果为文稿。 |
| 获准源码读取与候选文本修改 | 已接入，仅开发角色可使用，修改先保存在私有候选记录。 |
| 本地应用 | 需要桌面原生确认，并检查版本、授权与文件基线；写入结果可审查。 |
| 真实功能自测 | 尚无受隔离保护的执行器，显示未执行。 |
| 用户提交核验 | 尚未接入，由用户自行检查并提交。 |
| 测试环境部署、运行版本核验 | 尚未接入，显示受阻。 |
| 李力独立执行用例、缺陷回归与验收 | 尚未接入，测试计划不构成通过证据。 |
| 自动对外发送消息 | 未提供；讨论保存在项目工作簿中。 |

当前实现采用有限的源码读写动作与候选内容校验，没有提供运行任意程序的开发沙箱。不能据此声称已经完成设计方案中全部权限隔离、部署恢复或跨平台执行验收。

项目记录和候选源码属于本地私有数据，不应作为公开仓库示例、发布附件或共享模板提交。本文只使用通用项目和仓库名称。
