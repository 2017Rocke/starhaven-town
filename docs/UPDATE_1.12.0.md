# 星栖小镇 1.12.0 · 双向街道与环村路网

发布日期：2026-11-13

这一版把村庄的道路重做了一遍。以前村里只有四条横路，而且是「一条街两侧停车」的画法：房子挤在路两边，最南一排干脆没有路。现在每排房子门口都有自己的双向下街，东西两头再接上环村路，整座村子第一次连成一张完整的路网。

## 以前的三个问题

| 问题 | 表现 |
|---|---|
| 路太少 | 28 块地只有 4 条横路，第 5 排（y=1510）门口没有小径 |
| 路太窄 | 20 像素，画不出一条车道，更谈不上对向 |
| 没有竖路 | 住宅横向铺满，车从一条街到不了另一条街，只能原地折返 |

## 新的路网

行距从 340 加到 **380**，多出来的 40 像素做成街道和路肩：

```
380 行距 = 280 地块 + 100 走廊
100 走廊 = 18 路肩 + 64 街道 + 18 路肩
 64 街道 = 31 车道 + 2 中心线 + 31 车道
```

**五条横街**，每排房子门口一条：

| 街道 y | 服务哪一排 | 户数 |
|---|---|---|
| 308 | 第 1 排（y=150） | 5 |
| 688 | 第 2 排（y=530） | 6 |
| 1068 | 第 3 排（y=910） | 6 |
| 1448 | 第 4 排（y=1290） | 6 |
| 1828 | 第 5 排（y=1670） | 5 |

**两条环路**贴在地图东西两侧（x = -64..0 和 2880..2944），把五条横街的首尾接成一个闭环。这是本次改动的关键：有了环路，从任何一户开到任何另一户都有真实路径，不需要掉头，也没有断头路。

## 村心广场保持步行区

村心那张 960×660 的老地图位置没有动。第 1、2 排的街道本来会从广场背后穿过，现在它们在广场边缘断开，形成两个 T 字路口 —— 广场仍然是步行区，过路车辆走环路绕行。

## 站点、地块和美术都没有动

| 项目 | 变化 |
|---|---|
| 地块尺寸 | 320 × 280，不变 |
| 房屋美术 | 一行代码没改 |
| 村心 | 960 × 660 @ (960, 330)，不变 |
| 北部森林 | y -520..0，不变 |
| 星探路线 | 林道 x 1367..1393 仍未被占，路线不穿房、不压路 |
| 居民地块编号 | 完全不变，只有坐标跟着行距平移 |

世界因此从 2880 × 2200 变成 **3008 × 2460**。

## 路网定义只有一份

后端把路网随地图数据一起发给前端：

```json
"road":    { "width": 64, "verge": 18 },
"streets": [308, 688, 1068, 1448, 1828],
"rings":   [-64, 2880]
```

地图绘制和巡逻路线都读这一份数据，不再各自根据行距去猜。旧存档里没有这些字段时，前端会退回原来的推算逻辑，不会白屏。

## 验证方式

改动不是靠肉眼确认的，而是在两处机械校验：

**几何校验**：把 `worldBackground()` 的绘制逻辑用脚本复现一遍铺成像素，再做泛洪填充。

| 检查项 | 结果 |
|---|---|
| 地块压路 | 0 |
| 地块压村心 | 0 |
| 地块互相重叠 | 0 |
| 地块越出世界 | 0 |
| 缺小径的地块 | 0（28 块全部接上街道） |
| 道路连通性 | 250,368 / 250,368 个像素全连通 |
| 北部林道 | 未被挡住 |
| 星探路线 | 不穿房子、不压路 |

**端到端校验**：真启动后端，HTTP 取 `/api/state`，逐项核对世界尺寸、原点、街道、环路、路网宽度和 28 块地，并确认没有任何居民站在街上。

新增的单元测试 `test_every_plot_has_a_street_and_the_roads_stay_clear` 会把上面这套检查固化下来：以后任何人改行距或加地块，压路或断路都会直接测试失败。

## 升级说明

直接覆盖安装即可。居民的地块编号存在存档里，位置由地块编号在启动时重新计算，所以升级后房子会在地图上换位置，这是预期行为；居民身份、记忆、聊天记录、模型设置都不受影响。

## 已知限制

- 居民立绘、院子和门牌的相对位置未变，但行距变大后，空地在视觉上比之前松。若觉得太空，可在后续版本给空地补绿化。
- 警车仍是 1.11.0 的「一条街来回」路线。沿街逐户停靠的巡逻要等下一版。
- Windows 安装包与 macOS 安装包未在本次一并重建。
