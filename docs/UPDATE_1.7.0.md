# 星栖小镇 1.7.0 功能迭代说明

更新日期：2026-11-11

本次更新让星探拥有可以真正采集 GitHub 项目的观察站，并将居民住宅、职业道具与人物形象统一到更清晰的像素风格。内容包含此前尚未单独发布的 1.6.0 住宅与形象改进。

## 一、星探的观察站

星探保留「开源项目研究员」身份，增加「小镇采集员」职责：寻找公开项目、带回真实材料、整理并标注风险，供后续研究使用。

可以从左侧「观察站」、地图上的观察站建筑或材料架、星探角色卡中的住处进入工作区。点击居民仍可与星探对话。

| 场景与物件 | 对应的实际用途 |
| --- | --- |
| 院子里的材料架与原木 | 已保存的项目资料包，包括基础信息、来源和取得的源码 |
| 手推车与居民活动 | 展示当前真实采集阶段，整理材料时才显示运输中的原木 |
| 室内资料书架 | 展示已连接研究目录中的真实报告，保留原日期和出处 |
| 项目材料卡 | 搜索项目、分类或作者，打开来源、文件目录与风险详情 |

材料架画面最多显示 **6 捆原木**，数量标签显示实际库存；一捆对应一个项目资料包，可以包含多个文件。材料库当前没有项目数量上限，受硬盘空间与性能限制，尚无满仓、扩建或容量升级玩法。

## 二、三步真实采集

点击「让星探出发」后，界面跟随后台任务展示进度。

| 游戏里的动作 | 实际执行的工作 | 完成依据 |
| --- | --- | --- |
| 出门采集 | 在 GitHub 搜索并筛选公开项目 | 取得候选项，过滤不符合条件或已经收录的项目 |
| 搬回原木 | 取得项目基础信息、公开作者资料与固定提交的源码 | 实际下载并提取文件，保留来源和版本记录 |
| 整理材料 | 去重、分类、静态初筛并保存 | 文件成功落盘后写入材料账本，材料数量才增加 |

首版覆盖 AI、开发工具、自托管、效率、知识管理五类主题。默认筛选近 **180 天有更新、至少 1,000 Star** 的项目，按累计 Star 排序；这不是 GitHub 每日新增 Star 热榜。排除 Fork、归档项目、资料合集、未确认开源许可和历史已收录项目。

单轮默认最多采集 **3 个项目**，可配置为 **1–5 个**。候选不足、下载失败或限流时会如实报告，不为凑数量生成材料。同一时间只运行一个采集任务。

材料库按仓库唯一标识及不区分大小写的历史名称进行全历史去重。升级、关闭后重开不会清空去重记录；当前也不会自动为已收录仓库追加新的版本快照。

## 三、材料详情与风险记录

材料卡与详情包括项目名称、用途简介、分类、Star 数、主要语言、许可证、作者或组织的公开基础信息、仓库链接、固定提交、源码文件目录、原始说明、提取与扫描覆盖范围，以及脱敏后的风险线索。

当前是「材料采集与初筛」，尚不生成完整的行业研究、核心代码逻辑讲解、作者背景评价或采用建议。原木入库不会自动变成已完成的研究书籍。

采集使用 GitHub 官方公开接口与源码下载地址，不读取或附带用户 GitHub 密钥，不执行下载的代码或安装依赖。第三方说明以纯文本展示；原始源码与 README 不会自动发送给聊天模型。聊天只获得受限的材料数量和任务阶段摘要。

风险记录涵盖疑似凭据、联网、安装脚本、权限、遥测等静态线索。**规则命中需要复核，未发现线索也不代表绝对安全。** 界面中的疑似密钥脱敏展示，源码本身仍应视为不可信材料。

下载、展开和扫描具有资源限制：压缩包最大 24 MiB、展开总量最大 64 MiB、单文件最大 4 MiB、最多 6,000 个文件，并检查危险路径、符号链接、Windows 保留名称及大小写冲突。跳过文件或不完整提取会记录缺口，不能视为完整源码审计。

## 四、每日安排与中断处理

- 每日自动采集**默认关闭**，预设时间为北京时间 **09:00**，预设每次上限为 3 个项目，可调整为 1–5 个；在观察站调整后点击「保存安排」生效。
- 只在应用运行且网络可用时执行；完全退出应用后停止。macOS 关闭窗口只是隐藏，应用仍在后台时安排可能继续执行。
- 同一天最多触发一次自动采集；重新打开只检查当天到时的安排，不补跑此前多天。当日已读取到独立研究流程的报告时，不再重复自动出发。
- 网络故障、GitHub 匿名限流、部分成功和失败都有真实状态、原因与阶段足迹。应用重启后将未完成任务标为中断，保留已经入库的材料；再次出发会跳过这些材料。

这一安排属于桌面应用内采集，不会更改已有独立研究任务或将其自动化调度迁移到小镇。

## 五、居民住宅与角色形象

九类居民住宅采用统一像素网格、阶梯轮廓、瓦片、木石材质和院落道具。房屋主体根据职业确定，兴趣补充特色装饰，而不是根据居民名字固定绘制。

- 开发与音乐结合时可形成带乐器特色的节拍工坊。
- 架构与行情兴趣结合时可形成蓝图研舍。
- 养鸡相关角色拥有带鸡窝、饲料和饮水设施的暖羽鸡舍。

新增工程师、音乐人、建筑师、牧场伙伴、学者、画家 **6 款像素形象**，连同原有形象共 **10 款可选装扮**。创建居民和编辑角色档案时都可选择；换装保留职业、住处、记忆与聊天。

已有居民启动后使用新的住宅设计并保留原地块。星探旧版默认职责文字会更新为研究员兼采集员；已有自定义角色资料保留。观察站中的材料架、木材、工具、手推车和书架采用更清晰的像素造型，并适配暖绿原野与星夜营地皮肤。

## 六、升级、数据与平台状态

居民、聊天、偏好与观察站材料保存在应用包以外。观察站使用个人数据目录下的 `scout-workshop/`，其中包括独立数据库与 `materials/` 源码目录；已有研究目录仅只读登记，不移动或覆盖原文件。备份前请完全退出应用，再复制整个个人数据目录。

Mac 与 Windows 的构建脚本均已纳入采集模块。本次已有 **macOS arm64 1.7.0** 本地构建与安装验证；**Windows 1.7.0 安装包和 Intel Mac 安装包尚未重新生成、验收**。源码版本号不代表各平台同版本安装包已经发布；公开下载以 GitHub Releases 中实际提供的文件为准。

### 合入的 Windows 1809 修复

本次源码整合保留上游 `d0715bf`（1.5.1）的 Windows 修复，整体版本保持 1.7.0：

- 支持使用放在程序旁的固定版 WebView2 运行时；现有构建脚本不会默认把该运行时打入安装包。
- 针对白屏与无效窗口句柄问题，1809 默认启用 `--no-sandbox` 兼容模式；较新系统先使用默认隔离，初始化异常时也会尝试一次兼容模式。该方式会关闭浏览器进程沙箱，详见 [Windows 说明](WINDOWS.md)。
- 默认数据目录不可写时回退到程序目录的 `data/`；临时目录不可用时改用实际数据目录。通过菜单确认实际位置后再备份，便携版更换解压目录不会自动迁移回退目录内的数据。

上游提交记录 `10.0.17763.379` 启动自检通过，包括页面标题、居民加载和正常退出。**这是上游已有记录，本轮未在该系统复验，也不等于 1.7.0 采集功能、安装升级与完整运行均已验收。** 已有本地 Mac 安装包在此次源码合并前构建；此次源码整合未重新发布安装包。
