# 小镇皮肤开发

皮肤位于 `web/skins/`。当前提供「暖绿原野」和「星夜营地」，在页面右上角「小镇设置」切换。选择通过 `POST /api/preferences` 的 `selected_skin` 保存到本地 SQLite，不依赖模型连接。桌面应用重启或更换本地端口后，仍能恢复已选皮肤。

浏览器的 `localStorage`（键为 `starhaven:skin`）只用于加载时的外观缓存。页面首次读到 `/api/state` 后，使用其中的 `selected_skin` 恢复数据库记录；后续后台状态刷新不会覆盖用户正在进行的新选择。快速连续换装按顺序保存。保存失败会保留当前外观并提示重试，不把缓存冒充持久保存。

## 添加一件皮肤

1. 复制 `web/skins/template.css`，例如命名为 `autumn.css`。
2. 将文件中的 `data-skin="template"` 全部改成 `data-skin="autumn"`。
3. 在 `web/skins/manifest.json` 的 `skins` 数组中登记：

```json
{
  "id": "autumn",
  "name": "秋日麦田",
  "description": "金黄树叶与丰收时节",
  "css": "/skins/autumn.css"
}
```

4. 重启开发服务或刷新页面，在「小镇设置」选择新皮肤。
5. 检查小镇、任务板、成长册、聊天记录、角色档案、设置弹窗及窄屏布局，然后将 CSS 与清单一起提交。

`id` 必须以小写字母开头，只能包含小写字母、数字、短横线，最长 40 字符，不可重复。CSS 路径必须精确等于 `/skins/<id>.css`，不能填写外部地址、相对路径或任意本地路径。名称最多 40 字符，清单最多加载前 20 件有效皮肤。

## 外观约定

通用样式位于 `web/app.css`，原有暖绿样式是可靠的默认外观。CSS 变量可控制基础色彩与设置界面；现有页面还包含具体颜色，因此完整换色应参照 `starlight.css` 对对应组件补充规则。

每条覆盖规则都用 `[data-skin="你的ID"]` 限定作用范围。不要修改 DOM、功能按钮、表单语义、人物资料或工作数据；不要通过隐藏错误提示、缩小文字、覆盖层拦截点击来改变功能。地图可使用 CSS 滤镜调整气氛，人物应保持清楚可辨。

目前皮肤契约负责主题 CSS，不包含执行脚本、安装插件、在线皮肤商店、自动更新或自定义头像上传。需要新增地图和角色素材时，应通过正常代码评审扩展资源清单，保持素材随应用一起发布。

## 地图素材的一致性

新增场景以 `web/assets/town.svg` 为画风基准：使用 3–8 个设计像素的阶梯边缘、分层树冠、错缝瓦片、木板与十字窗格，避免平滑斜线、渐变高光和大片无纹理色块。世界坐标与像素密度沿用村心，不为不同职业单独缩放素材。房屋的职业特征通过屋顶、门牌、小道具与庭院表达，居民主题色只点缀少量细节。

原地图、新房屋和村外田园共用 `--map-filter`，夜景皮肤同时覆盖这些场景。角色、标签与按钮保留可辨认的对比度。新增外观后检查村心与住宅交界、满员住宅、无人入住田园、深色主题和窄屏，避免只有单栋房屋好看、拼到地图上风格割裂。

## 本地资源约束

加载器先从随应用发布的清单选择 CSS，读取并检查内容后才应用已检查的字节。每个 CSS 文件不得超过 100,000 字符。包含外部资源引用、导入语句、命名空间语句或反斜杠转义的 CSS 会被拒绝；不提供用户粘贴 CSS、任意 URL 或在线样式导入入口。

因此请使用纯颜色、渐变、边框、阴影、现有本地图片的滤镜和已包含的字体。不要加入 `@import`、`@namespace`、`url(...)` 或 CSS 转义字符，连注释中也应避免这些字符串。该约束阻止皮肤加载外部资源；皮肤仍应视为项目代码，合并前检查可读性与交互，不承诺运行任意第三方 CSS 的沙箱。

## 验收清单

- 深浅主题下正文、辅助说明、错误、占位文字、禁用状态都可辨认。
- 键盘焦点清楚可见，切换主题不会清空草稿或关闭正在进行的对话。
- 在 390px 手机宽度和桌面宽度中无横向溢出，设置入口可点击。
- 刷新、重启桌面应用或更换服务端口后仍保留选择；删除已保存皮肤时回退到清单默认主题。服务端也校验已登记的本地皮肤编号，非法设置不写入数据库。
- CSS 加载失败保留已有界面，并在设置弹窗显示原因。
- 不添加网络依赖；角色、地图与主题可以离线展示。
- 添加动态效果时尊重 `prefers-reduced-motion`。
