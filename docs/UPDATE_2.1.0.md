# 星栖小镇 2.1.0 · 严格预算扩围、跨机器快照与按岗位分题

更新日期：2026-11-16。版本标签：`v2.1.0`。下载与构建结果见 [GitHub Release](https://github.com/2017Rocke/starhaven-town/releases/tag/v2.1.0)。

本版在 2.0 的成长署与受控协作之上，解决三件影响日常使用的事：DeepSeek 端点可以开启严格预算；小镇状态可以打包带到另一台电脑继续；成长署不再给所有岗位出同一道题。

## DeepSeek 可以开启严格预算

严格预算原先只认 OpenAI 的 `gpt-4o` 系列，因为预算按 `完整请求的 UTF-8 字节数 + 512 + 单次最大输出` 预留，这依赖四项可验证行为：`max_tokens` 被字面执行、`usage` 返回整数且 `total == prompt + completion`、隐藏推理计入 `completion_tokens`、输入 `prompt_tokens` 不超过请求字节数。

对 `https://api.deepseek.com` 的 `deepseek-flash` 与 `deepseek-v4-pro` 实测六次受控调用（16 到 4096 的输出上限）后，四项全部成立，因此新增已验证档案 `deepseek-reasoning-v1`。端点或模型名不完全匹配时仍判为未验证，只保留普通聊天审计。

这两个是推理模型，推理 token 计入输出上限：实测 1024 输出上限下，一次岗位训练有 746 个 token 花在推理上、正文被截断到 448 字。**建议把「单次最大输出 Token」调到 4096**。同时把该档案的 socket 超时从 20 秒提高到 120 秒——非流式请求要等整个答案生成完才回正文，20 秒会让训练的第二、三次调用超时，而超时仍按预留量全额记账。

## 换电脑不必重新训练

新增 `scripts/state_bundle.py`，提供 `export` / `inspect` / `restore`：

```sh
python scripts/state_bundle.py export  --data <数据目录> --out state/town-state.zip --strip-chat
python scripts/state_bundle.py inspect state/town-state.zip
python scripts/state_bundle.py restore state/town-state.zip --data <安装目录>/data
```

- 收录 `town.sqlite3`、`workspaces/` 下的成果正文、星探采集索引、两署档案，以及 `provider.json` 的端点与模型名
- 排除浏览器缓存、日志、升级备份、锁文件、SQLite 边车文件，以及星探下载的约 65 MB 第三方源码
- `--strip-chat` 移除聊天正文，保留居民、训练、成果、预算与审计记录
- 导出前用小镇自己的实例锁确认应用已退出；每个文件记 SHA-256，恢复时逐字节校验，被改动就拒绝
- **模型密钥不随包迁移**：密钥保存在操作系统凭据管理器里、按数据目录路径命名，换机器必须重新填写

`state/` 目录只保留一个固定文件名的快照，步骤见 [跨电脑迁移小镇状态](STATE_BUNDLE.md)。

## 成长署按岗位分题

原来只有两套独立检查题型（区间判定、资料交付），除开发类岗位外所有人拿到的是同一道「三项成立才可交付」，于是大部分成果都是同一个模板的变体。本版增加两组岗位关键词与对应题型：

| 岗位关键词 | 任务 | 独立检查 |
| --- | --- | --- |
| 美术、视觉、景观、绿地、风景、配色、像素 | 视觉设计 | 画布边界：`rect` 能否放进 `canvas` 且四边各留 `margin` |
| 动画、动效、特效、关键帧、动作、帧 | 动效设计 | 动效预算：帧数不超上限，且 `frames×frame_ms` 不超预算 |

同时修正答案分布：每套 8 个案例固定 4 个 true、4 个 false。此前资料交付题只有 1 个正例，「永远回答 false」就能得 7/8，基线必然满分、参考收益永远测不出来。

## 对话里能看到自己的成果目录

问居民「你最近有什么成果」时，它会答「没印象、记录都是空的」——因为成果登记在数据库里，却从来没有进过对话上下文。现在上下文包含该居民最近 10 条成果的元数据（编号前 8 位、标题、类型、日期、字节数、是否已验收），并在固定规则里说明：登记不等于执行过，正文只有被引用时才以参考资料出现。正文仍不进入上下文，避免绕过引用与权限检查。

## 更容易看清发生了什么

- **训练卡片显示具体任务要求**：此前只显示一句通用目标，真实的任务说明存在 `v2_tasks.prompt` 里但接口没带出来。现在每张卡片有「查看任务要求」，展开就是岗位、培养方向、岗位要求与练习主题，答案仍然只留在后端。
- **预算拒绝按原因分别报错**：此前四个不同限制共用一句「今日居民共享预算不足」。实测一次「单次预留 30,209 超过单次上限 32,000」被误报成「今日额度用光」，按提示提高每日额度也不可能解决。现在分别提示单次超限、累计额度、今日额度、今日调用次数，并带上实际数值。

## 支持范围与升级

- 严格预算与自动训练仍只对已验证档案开放：OpenAI `gpt-4o` 系列（`openai-text-bpe-v1`）与 DeepSeek `deepseek-flash`、`deepseek-v4-pro`（`deepseek-reasoning-v1`）。其他兼容端点保留普通聊天，不能开启受控训练。
- 新安装仍是十一位初始居民、最大容量三十三位；已有存档按稳定编号与迁移记录补入角色，不覆盖个人资料。
- 升级前请退出应用并复制整个数据目录。数据库结构变化由程序迁移，但附件与本次之后产生的记录不在旧备份里。
- Windows 构建在 `windows-2022` 上验证，不等于 Windows 10 `17763.379` 实机验收；Mac 产物默认 ad-hoc 签名，未完成 Apple Developer ID 公证。
