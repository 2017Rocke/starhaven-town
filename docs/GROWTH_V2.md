# 星栖小镇 V2.0 需求与实现说明

版本：`2.0.0`；更新日期：2026-11-14；实现基于上游提交 `2f79e53`。本文说明本版的产品逻辑和使用方式，安装包与发布结果见 [v2.0.0 Release](https://github.com/2017Rocke/starhaven-town/releases/tag/v2.0.0)。

本文承接 [原 V2.0 设计稿](DESIGN-v1.14-v2.md)，并纳入后续确认的“成长署作为 HR 自动培养居民”和“稽查署统一管理网络、API 与知识流转”两项需求。旧稿中的暂定版本、接口草案、默认参数和阶段范围以本文及当前代码为准。

## 1. 谁来决定居民产出什么

用户只需确定培养方向、参与居民、模型端点和预算。成长署按居民岗位和最近的训练记录生成基础任务，居民在授权范围内执行；用户有实际需求时，向领航提供整体项目目标。两类任务共用成果、权限和账务体系。

| 参与者 | 职责 | 决策边界 |
| --- | --- | --- |
| 所有者 | 确定方向、居民范围、预算，核准资料外发与技能，验收主观成果 | 权限扩张和恢复运行通过桌面原生窗口确认 |
| 成长署 / 成长官 | 依据岗位、近期任务和失败记录制定每日练习，保留训练与验收证据 | 使用内置岗位模板，不自行扩张网络、额度或居民范围 |
| 领航 | 将用户的整体项目目标匹配到最多三名已授权居民，建立文本交付任务 | 当前采用确定性岗位匹配，不是通用的多轮智能项目规划器 |
| 居民 | 根据任务说明生成方法、清单、分析、示例等成果 | 只生成文本，不执行模型给出的命令或程序 |
| 稽查署 / 网安稽查官 | 检查请求目的地、居民授权、资料读者及外发权限，记录放行和阻断依据 | 实际门禁由后端代码执行，警官的聊天回复不构成授权 |

成果链路为：**方向与授权 → 岗位计划 / 项目任务 → 调用前准入 → 文本成果 → 独立检查或人工验收 → 可追溯的知识与参考技能。**

## 2. 第一次使用

1. 在桌面版“小镇设置”中配置模型连接。严格预算和自动任务支持的连接范围见第 6 节。
2. 打开“成长册”中的成长署，或点击成长官的房屋，选择“培养与网络设置”。
3. 填写整体培养方向，选择参与居民、API 地址与模型，设置每日调用量、Token 额度、累计额度和单次上限。开启严格模式及自动安排与执行。
4. 在弹出的原生窗口核对内容并确认。网页本身只能发起确认请求。
5. 成长署会在应用运行期间自动生成当日计划并串行执行。可以在“训练与项目”查看状态、成果和本次独立检查的完整证据。
6. 有实际工作时，点击“给领航一个整体项目”，填写整体目标与验收标准；可以选择已登记且授权给参与居民的资料。

新安装自动训练默认关闭、预算策略暂停、居民范围为空，不会因为打开成长署就发起模型训练。仅配置模型连接不等于授予自动任务权限。

“立即暂停”会阻止后续受控调用，并尽力取消在途调用。“暂停该居民”对该居民的兼容聊天也生效；恢复需要重新确认培养与网络设置。已经发送的请求可能产生费用，暂停不抹除其账务记录。

纯浏览器开发模式可查看记录、管理本地文字草稿和执行收紧权限的操作；扩大授权、验收、启用技能等操作需要原生宿主。已有自动任务授权仍按服务运行状态生效。

## 3. 成长署自动培养

### 3.1 岗位与任务

每位获准居民每天最多生成一份计划，重复请求不会重复建计划。计划保存岗位、培养方向、最近 30 项任务画像及当时的授权版本。

| 岗位匹配 | 基础产出要求 |
| --- | --- |
| 测试、质检 | 边界值、相邻越界值、预期结果与复现步骤 |
| 产品、需求、协调、主管 | 用户场景、输入输出、优先级和可重复验收条件 |
| 开发、工程、架构 | 输入输出约束、算法说明、边界与测试样例 |
| 网安、稽查、治安 | 区分目的地授权与资料外发授权，记录拒绝原因和证据 |
| 研究、采集、分析 | 区分事实、推断与未知，明确来源和适用范围 |
| 其他岗位 | 可复用工作清单、实际示例、限制和验收方法 |

默认每天一项训练，可在授权时调整为最多三项。第一项带独立案例检查，其余为等待人工验收的岗位样稿。计划生成使用本地规则，不消耗模型调用额度；执行任务会消耗额度。

当前能力画像用于选择练习重点和提示近期缺口，尚不是完整的职业能力测评体系。居民聊天、字数增加、模型自述“已经掌握”均不会被当作能力提升证据。

### 3.2 独立检查与人工验收

一次带独立检查的训练通常包含三次模型调用：

1. **基线**：模型在不使用本次练习参考的情况下回答八个新案例。
2. **练习**：模型根据岗位、检查规则与既有授权参考，生成可复用方法和自行设计的例子。练习提示中不包含这八个案例及其标准答案。
3. **候选结果**：模型使用生成的方法，再回答同一组案例，由程序按固定规则判分。

当前案例覆盖边界判断和资料交付条件判断；这能核对有限任务上的行为，不能代替完整的开发、研究或测试专业评估。无工具执行、真实代码运行和模型参数训练。

候选答案全部正确，且相较基线至少多答对两题、三次调用的模型与端点一致，才记录“本次有对比改善的试验”。基线已经满分时，即使候选也满分也不记改善。原始回答、规则、参考版本哈希、调用编号和模型信息会保存，可重新计算分数。

客观训练通过后记录程序验收；主观样稿与真实项目成果由所有者填写验收依据并原生确认。页面区分“产出”“已验收”“独立检查通过”和“本次对比改善”。所有结论仅对应所保留的证据。

### 3.3 调度、取消与恢复

- 自动任务只在应用运行期间执行，后台训练串行；与同一居民的活动聊天互斥。
- 过期的日计划不会自动补跑。失败、阻止、取消和重启中断的任务需要明确重试；默认只允许一次尝试，可授权为最多两次。
- 重试使用新的独立案例，保留先前调用、费用、成果和不可变试验证据。
- 每项任务绑定自己的授权版本。修改策略后，旧任务须按当前授权明确重试；重试一项任务不会顺带重授权同计划的其他任务。
- 预算不足或权限不满足时停止该项执行，不进行无限重试。部分完成的成果仍保留。
- 撤销验收保留审计记录，并从当前合格产出统计中移除该验收。

## 4. 成果、知识与技能

### 4.1 成果来源

可在已完成的居民回复下“保存成果”，或在成长署“导入文字资料”。只有成功完成的助手回复可以标记为居民原回复；作者、原消息、任务编号、哈希与字节数均由后端推导。

修改内容会创建新版本，旧版本保留。人工导入、人工整理、居民原回复、训练成果、项目成果和交付副本分别标记来源。交付保留原作者和来源链，不把副本计作接收居民的原创产出。

文本保存在居民工作区的 `skills/books/materials/results` 分类下。路径由程序生成，不接受任意文件路径或可执行上传。文件先暂存、再登记、最后发布；意外退出后可恢复一致的待发布记录。读取、引用和计数时核对内容哈希；破损或被外部改写的文件不能继续当作有效证据。

### 4.2 资料权限与输入输出

新资料默认仅持有居民本地可读，不允许外发或交付。需要进一步使用时，在资料详情中设置并原生确认：

- **允许读取的居民**：哪些居民可以引用这份材料。
- **允许外发的目的地**：哪些已经核准的模型 API 可以收到这份材料。
- **交付权限**：是否可以把副本交给已获读取授权的居民。

允许某个模型端点联网，不代表允许把所有资料发给它。调用必须同时满足端点授权、居民授权、每份资料的读取和外发条件。

修订版、交付副本、使用材料生成的回复都会保留来源链。每次使用时递归复核全部来源；单独放宽副本权限不能解除源材料的限制。历史对话再次引用资料时也会复查，而不是只检查刚选择的附件。

用户在本地所有者界面可以查看材料。上述读者权限约束的是居民上下文与应用内流转，不是电脑上其他账户或进程的文件访问控制。人工复制粘贴到普通聊天中的新文字无法自动还原其来源；需受控流转的资料应通过登记和引用入口使用。

星探原有采集库和外部团队台账不会自动变成受控知识库。严格模式下不自动把旧外部报告全文放进对话；要引用其内容，应先显式导入文字资料并设置权限。

### 4.3 参考技能

技能是有版本的参考文字。将成果保存为 `skills / skill`，提交审查、查看风险和依赖，再通过原生窗口启用。

机检阻止超长正文、已知凭据特征和工具/执行/网络权限声明；链接、命令示例和指令覆盖措辞作为人工复核线索，不能据此宣称内容绝对安全。检查有效期 30 天，过期后不再引用，需重新提交审查。

每位居民最多启用五个版本；每次引用含依赖最多两个文本、总计 8 KiB。当前从已启用的有效记录中按提交时间从新到旧选择能容纳的完整依赖链，不实现语义检索或向量搜索。依赖须属于同一居民的明确版本；停用依赖会连带停用相关技能。技能不会增加执行、联网、派单或审批权限。

## 5. 产出约定与日记录

产出约定是额外可选的统计要求，不需要为每名居民逐一设置才能开始基础培养。可指定分类、类型、份数、单份最小字节数、最近多少天、是否必须验收和工作日。

新约定经原生确认后次日生效；停用也保留历史版本。按照北京时间统计，每份文件先独立检查条件与完整性，再按内容哈希去重；演示、人工导入、人工整理和交付副本不计模型原创产出。产出按发布时间计，验收按验收日期计。

在“培养计划 → 产出明细与日记录”查看计入证据、未计入原因和最近统计快照。撤销验收、证据变化会追加统计修订，旧快照保留。系统日期回退时暂停自动培养并要求核对时钟。

在严格模式下，已配置但未达成的有效约定会阻止普通聊天调用；基础训练仍可执行，以便居民完成要求。未配置约定或非安排日不会施加这一限制。它不替代任务的具体说明和验收条件。

## 6. API、网络与预算

### 6.1 出入口

| 通道 | 当前规则 |
| --- | --- |
| 桌面到本地服务 | 仅回环服务、来源与请求头检查；特权确认额外验证原生私有凭据 |
| 模型 API | 统一从 ProviderBridge 发出；检查协议、目的地、敏感内容和策略；禁止重定向和环境代理 |
| 严格模式调用 | 只允许明确居民及端点/模型组合，并在发送前再核对预算、来源、技能和撤销状态 |
| 星探 GitHub 采集 | 沿用 `api.github.com`、`codeload.github.com` 固定只读入口和稽查审计；属于独立公开采集流程 |
| Codex 外部调用 | 兼容模式标记外部未计量；严格模式、带受控资料的对话及自动训练禁止借此绕过门禁 |

这里限制的是小镇应用已经实现的请求入口，不是操作系统防火墙。GitHub 公开采集不使用模型 Token 额度，也不会获得向任意地址上传居民资料的能力。

### 6.2 当前可执行严格预算的模型

当前适配档案为 `openai-text-bpe-v1`，端点必须是 `https://api.openai.com/v1`，模型名必须为：

- `gpt-4o-mini`
- `gpt-4o-mini-2024-07-18`
- `gpt-4o`
- `gpt-4o-2024-08-06`
- `gpt-4o-2024-11-20`

请求使用文本 Chat Completions、`max_tokens` 输出上限和 `usage` 用量映射。其他兼容 API 与本机模型可以在兼容模式聊天，但当前不能开启自动训练或宣称具有同等额度保证。上列名称是代码中的支持清单，不保证账户当前有模型访问权限；本次没有调用真实付费模型验证在线可用性。

### 6.3 额度与结算

| 配置 | 初始值 |
| --- | --- |
| 自动任务 / 严格模式 | 关闭 / 关闭，初始暂停 |
| 每位居民每日额度 | 100,000 Token |
| 每位居民每日调用上限 | 12 次，聊天与训练共享 |
| 每位居民累计额度 | 3,000,000 Token |
| 单次完整请求上限 | 32,000 Token 的保守预留值 |
| 单次最大输出 | 1,024 Token |
| 每日基础任务 | 1 项，可配置为 1–3 项 |
| 每项任务最多尝试 | 1 次，可配置为最多 2 次且手动重试 |

当前是全局统一上限、各居民分别记账；支持单居民暂停，没有单居民不同额度覆盖项。培养和项目任务的每次模型调用都算入额度；一个带独立检查的任务通常消耗三次调用。

发送前在事务中预占“完整序列化请求的 UTF-8 字节数 + 512 余量 + 输出上限”，而不是只计算用户最后一句话。实际提供有效 `usage` 后按回执结算；已发出但无可靠用量回执时保留预占量作为未知账务。尚未发送的请求可释放。迟到的有效回执只由持有该调用的服务端工作线程更正，并追加记录。

取消、超时、跨日、重启或更换策略均不清空已经发生的费用。账务归入准入当日；实际用量超过预留会记录真实值并暂停后续受控请求。界面展示今日记账、在途预留、每日余额、调用次数和累计余额。

Token 额度不是人民币或美元预算。预留是保守估算，未计量的外部调用也不是免费；实际收费仍以模型账户账单为准。

## 7. 原生确认与审计

培养策略、资料权限、人工验收、产出约定和技能启用均通过一次性确认意图处理。意图绑定当时内容与权限快照，有效期五分钟。原生宿主从后端取得权威摘要，展示后提交确认；内容或权限已变化、过期、重复使用或跨进程重启的意图会拒绝。

宿主私有凭据通过继承的 stdin 管道传给后端，不放入网页、命令行参数、环境变量或就绪文件。页面消息只能传意图编号。暂停、撤销验收和停用技能这类收紧操作可以立即执行。

审计事件采用只追加哈希链，保留成果、授权、训练和账务事件。该机制用于发现本地记录异常，不是面对拥有系统管理权限者的外部存证服务。

## 8. 存档迁移与实现位置

首次升级 V2 数据结构前，使用 SQLite 在线备份将原 `town.sqlite3` 保存到数据目录的 `backups/before-v2-*.sqlite3`，确认数据库完整性后再迁移。现有居民、聊天、记忆和团队资料保留。

全新小镇共十一位初始居民，包含新增成长官；最大容量仍为三十三位。满镇时不挤走居民，成长署工作区照常可用；有空地时可按迁移规则补入成长官。角色与工作区不互为运行前提。

| 文件 | 实现职责 |
| --- | --- |
| `town_store.py` | 数据结构、升级备份、事件链和共享校验 |
| `town_growth.py` | HR 计划、项目任务、调度、独立判分和证据 |
| `town_artifacts.py` | 不可变文字成果、来源与权限继承、交付及恢复 |
| `town_budget.py` | 授权准入、共享预算、发送前复核、用量结算与余额 |
| `town_skills.py` | 参考技能、依赖、产出约定及每日快照 |
| `town_owner_actions.py` | 原生确认意图、快照绑定和一次性裁决 |
| `server.py`、`provider_bridge.py`、`town_security.py` | API、聊天上下文、调用适配和统一稽查门禁 |
| `desktop/WindowsHost.cs`、`desktop/App.swift` | 原生私有通道和确认窗口 |
| `web/growth-workspace.js`、`.css` | 培养、任务、成果、技能和预算界面 |

新增模块已纳入 Windows、macOS 构建与源码导出清单。详细数据使用 `v2_*` 表，原安全档案继续使用原来的独立存储。

回退前先退出应用并完整复制当前数据目录；V2 新增成果、账务和证据也在其中。需要恢复升级前状态时，在另一份数据目录副本中恢复对应数据库备份并使用匹配版本，不直接覆盖唯一存档。数据库备份不包含全部附件，也不包含此后产生的新记录。

## 9. 本次交付边界

本版安装器由 GitHub 发布流水线从不可变标签构建。Windows 原生宿主已有本地编译验证，macOS 构建由对应平台的流水线执行；各平台结果以本版 Actions 记录为准。真实模型费用和完整原生确认操作未做在线验收。

开发期间已有离线后端和浏览器验证记录，收尾阶段按所有者要求未继续本地回归。发布门禁使用本次确切提交的 Checks 和三平台构建、安装检查结果，不能以早先的本地检查代替发布证据。Windows Server 2022 检查不代表旧版 Windows 10 实机认证；Mac 默认 ad-hoc 签名不代表 Apple 公证。
