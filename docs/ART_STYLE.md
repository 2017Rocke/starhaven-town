# 建筑美术规范

## 同一坐标与比例

- `StarhavenHouseArt.house(agent)` 和 `yard(agent)` 返回使用 320×280 地块坐标的 SVG 分组。调用方不再增加旧的 `translate(40 18)` 偏移。
- `layout(agent)` 提供 `hit` 矩形，以及 `label`、`resident`、`doorstep` 三个 `{x,y}` 锚点。房屋标签、交互和立绘应读取这些信息。
- 主门沿地块中心线布置。住宅正门到院外的中央通道留给居民；职业设施布置在两侧。地标建筑的下缘需避开村心主街。
- 细节使用整数像素，主体尽量使用 4 像素结构、2 像素修饰。边缘采用阶梯轮廓，避免曲线与模糊描边；地图缩放保持横纵比例一致。

## 材质与识别

屋顶、墙面、木料和石料分别保留基础、亮面、暗面层级，光源统一来自左上。用瓦缝、木板接缝、窗框和地基表达材质，减少无意义的密集纹理。门窗尺寸应与居民立绘协调。

职业特色至少有一个易辨认的大轮廓或道具组合：观测顶、旗塔、鸡舍、舞台、制图台、书架、晾鱼架等。主题装饰不能挡住门口或遮盖相邻地块。

夜景沿用统一的地图滤镜，窗灯与门灯在独立叠层中表现；不要为单栋建筑另做一套不一致的夜间颜色。日间建筑与夜间窗灯使用两个同坐标的根 SVG，滤镜作用于日间 SVG，避免 macOS WebKit 对内部 SVG 分组滤镜的兼容差异。窗前摆件不能与发光玻璃重叠，否则会被上层窗灯覆盖。昼夜两种皮肤均需检查。

## 渲染与验证

操作真实 SVG 节点时使用 `localName`、`getAttribute()` 和 `setAttribute()`。不要依赖测试替身的 `name` 或 `attrs` 字段。需要收窄细节时，应对左右边缘分别取整，保持相接边缘一致；不要在最终图层上做不等比拉伸。

几何检查覆盖所有房屋类别、像素坐标和尺寸、门口通道与布局锚点。自动检查不能替代真实浏览器观察：至少检查一栋普通住宅、指挥所、观察站，以及日间和夜间。桌面发布前还需在原生窗口核对夜景，不能仅凭 Chromium 预览判断 Mac 绘制效果。修改村心地标时，还需核对材料架点击、星探行程和建筑之间的道路。
