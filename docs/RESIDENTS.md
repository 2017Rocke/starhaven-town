# 初始居民与个人存档

当前 2.0.0 源码为全新的小镇提供十一位初始居民。领航和星探是原有核心角色；吉吉、东日、科德、爬山佬来自 1.8.0 的公开角色设定，后续加入两位警官、研发小组和成长官。

| 居民 | 角色与兴趣 | 住处 |
| --- | --- | --- |
| 领航 | 协调目标、计划与进度 | 指挥所 |
| 星探 | 开源研究、公开项目采集 | 观察站 |
| 吉吉 | 开发、测试、整理代码，喜欢摇滚 | 节拍工坊 |
| 东日 | 架构、重构、底层逻辑，喜欢行情研究 | 蓝图研舍 |
| 科德 | 养鸡、育雏与日常照料，耐心直接 | 暖羽鸡舍 |
| 爬山佬 | 爬山、跑步与交际，做事有原则 | 温馨小屋 |
| 巡检警官 | 文件巡检与证据记录 | 警察署 |
| 网安稽查官 | 网络、API 与资料流转门禁 | 稽查署 |
| 杨辉 | 产品需求与验收条件 | 产品经理住宅 |
| 阿力哥 | 测试、边界检查与问题复现 | 测试工程师住宅 |
| 成长官 | HR 岗位培养、基础任务与能力证据 | 成长署 |

这些内容是可编辑的角色设定，不代表已验证的工作能力或投资业绩。公开版本整理了措辞，去掉未经验证的收益表述；不会修改作者已有存档中的个人设定。

## 新安装与升级

没有居民的全新数据目录初始化原有角色后，按迁移规则加入两署、研发小组和成长官，共十一位。角色拥有独立档案和空白聊天记录；无需导入作者的数据库即可生成职业房屋。小镇最大容量三十三位。

已有小镇升级时保留个人档案、记忆和聊天，迁移按稳定编号和完成标记补入新角色；研发小组沿用其已有地块调整规则，不以仓库配置覆盖个人编辑。修改过的居民不会在重启后恢复出厂设置。满镇时不会挤走其他居民，成长署工作区仍可使用。

## 公开配置范围

四位新增初始居民的配置在 [`defaults/residents.json`](../defaults/residents.json)。每个条目只允许名字、职业、性格、简介、外观、颜色、公开编号和初始地块编号。领航和星探的默认档案在 `server.py`。

仓库与安装包不包含作者的聊天、明确记忆、模型配置、凭据、采集源码库或个人团队台账。公开编号使用可读名称，不复制个人存档中的随机编号。该文件是随版本发布的初始配置，不是持续上传个人存档的同步服务。

新角色使用用户自己配置的模型服务进行对话。角色设定和房屋不会自动赋予系统命令或 Skill 执行权限；基础训练与项目文本任务需先获得培养范围、端点和预算授权，详见 [V2.0 说明](GROWTH_V2.md)。
